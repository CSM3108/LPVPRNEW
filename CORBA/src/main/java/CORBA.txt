CORBA

============================================

Create structure

src.main.java
- StringService.idl
- StringServiceImpl.java
- Server.java
- Client.java

Run these commands in src/main/java path

1. Compile the .idl file : idlj -fall StringService.idl
This will generate .java files :
- _StringServiceStub : The client-side proxy that represents the remote server object
- StringService (I) : the contract, this extends StringServiceOperations
- StringServiceHelper : Utility Methods for server side functions (standards)
- StringServiceHolder : Holder classes wrap the value into wrapper (for pass by reference) to allow modification by the called method
- StringServiceOperations (I) : actual interface used by server side
- StringServicePOA : The server-side skeleton that handles network communication (Portable Object Adapter)

-f : generate client side files
-a : generate server side files
-ll : generate linking files for both
Without -fall only stub file will be generated

2. javac *.java
Compile all java files

2. orbd -ORBInitialPort 1050 -ORBInitialHost localhost
Runs the naming service - Object Request Broker Daemon
Maps human-readable service names to actual object references

3. java Server -ORBInitialPort 1050 -ORBInitialHost localhost
running the compiled Server class and passing args

4. 3. java Client -ORBInitialPort 1050 -ORBInitialHost localhost
running the compiled Server Client and passing args

Dont need to define a port for Server, the CORBA automcatically assigns available the port to server



Server.java 
- ORB orb creates Object Request Broker using args, ORB manages network communication, marshalling-unmarshalling
- resolve_initial_references("RootPOA") asks ORB for the Root POA (RootPOA is a standard constant string for ORB)
- POAHelper.narrow() converts generic CORBA object to specific POA type
- POA manages lifecycle of servant objects
- rootPOA.servant_to_reference(servant) converts servant plain java object to CORBA reference, assigns a unique ID to servant and binds server to a port
- StringServiceHelper.narrow(ref) converts ref to StringService interface
- resolve_initial_references("NameService") asks ORB for naming service object
- NamingContextExtHelper.narrow() converts CORBA Object to NamingContextExt object
- ncRef.rebind(ncRef.to_name("StringService"), href) register our object with a name in the Naming Context
- rootPOA.the_POAManager().activate() POA is not HOLDING state --> ACTIVE state
- orb.run() runs the ORB event loop

CORBA = Common Object Request Broker Architecture
A standard that allows software components written in different programming languages and running on different machines to communicate with each other.

Components:

1. ORB (Object Request Broker)
The "bus" that carries requests between clients and servers

2. IDL (Interface Definition Language)
Language-neutral way to describe what methods an object provides

3. Stubs & Skeletons
Code that handles networking details automatically

4. Naming Service
Directory that maps names to object locations

1. What is CORBA?
Answer:
CORBA (Common Object Request Broker Architecture) is a middleware technology used for communication between distributed objects on different machines.

2. What is the purpose of CORBA?
Answer:
CORBA enables distributed applications to communicate with each other regardless of programming language or platform.

3. What is ORB?
Answer:
ORB (Object Request Broker) is the middleware component that manages communication between client and server objects.
It:
locates remote objects,
forwards requests,
returns responses.

4. What is IDL?
Answer:
IDL (Interface Definition Language) is used to define remote object interfaces in CORBA.
It is language-independent.

5. Why is IDL required?
Answer:
IDL allows communication between applications written in different programming languages.

6. What is a Stub in CORBA?
Answer:
Stub is the client-side proxy object that forwards method calls to the server object.

7. What is Skeleton in CORBA?
Answer:
Skeleton is the server-side dispatcher that receives client requests and invokes actual server methods.

8. What is POA?
Answer:
POA stands for:
Portable Object Adapter
It connects servant objects with the ORB and manages object activation.

9. What is a Servant in CORBA?
Answer:
Servant is the actual implementation object that performs the requested operations.
Example:
StringServiceImpl

10. What is Naming Service?
Answer:
Naming Service stores object references and allows clients to locate remote objects using names.

11. What is ORBD?
Answer:
ORBD (Object Request Broker Daemon) provides CORBA naming and activation services.

12. Why do we use orbd?
Answer:
orbd starts the Naming Service so that clients can locate server objects.

13. Explain idlj -fall StringService.idl
Answer:
This command generates:
stub,
skeleton,
helper,
holder,
POA classes
from the IDL file.

14. What does javac *.java do?
Answer:
It compiles all Java source files into .class files.

15. Why do we use -ORBInitialPort 1050?
Answer:
It specifies the port number of the CORBA Naming Service.

16. Why do we use -ORBInitialHost localhost?
Answer:
It specifies the machine where the Naming Service is running.
localhost means same machine.

17. Difference between RMI and CORBA?
RMI	CORBA
Java specific	Language independent
Uses Remote Interface	Uses IDL
Easier	More complex
Java-to-Java communication	Cross-language communication

18. What is distributed computing?
Answer:
Distributed computing is a system where multiple computers communicate and work together to solve problems.

19. What are the advantages of CORBA?
Answer:
Platform independent
Language independent
Supports distributed systems
Reusable components
Object-oriented communication

20. What are the disadvantages of CORBA?
Answer:
Complex architecture
Difficult debugging
Performance overhead
Configuration complexity

21. Why is CORBA removed from newer Java versions?
Answer:
CORBA support was removed after Java 8 because newer distributed technologies replaced it.

22. Which Java version supports CORBA?
Answer:
Java 8

23. Explain the flow of CORBA application.
Answer:
Define interface using IDL
Generate CORBA classes using idlj
Implement servant class
Start ORBD Naming Service
Run server
Run client
Client invokes remote methods

24. What is object brokering?
Answer:
Object brokering means managing communication between distributed objects using ORB.

25. What is the role of resolve_initial_references()?
Answer:
It obtains references to CORBA services like Naming Service and RootPOA.

26. What is rebind() in CORBA?
Answer:
rebind() registers or updates the object reference in Naming Service.

27. What is marshalling in CORBA?
Answer:
Marshalling converts objects/data into transmissible format for network communication.

28. What is unmarshalling?
Answer:
Unmarshalling reconstructs transmitted data back into objects at receiver side.

29. What happens when client calls a remote method?
Answer:
Client calls stub method
Stub sends request to ORB
ORB forwards request to server
Server executes method
Result returns to client

30. What is the role of orb.run()?
Answer:
orb.run() keeps the CORBA server active and listening for client requests.
