Token Ring

Token Ring Mutual Exclusion — Complete Working

Objective
The objective of Token Ring Mutual Exclusion is:
Ensure only one process enters Critical Section at a timeEnsure\ only\ one\ process\ enters\ Critical\ Section\ at\ a\ timeEnsure only one process enters Critical Section at a time
using a unique token.

Basic Concept
Processes are arranged logically in a ring.
One special message called:
TOKEN
circulates continuously.
Only the process holding the token can enter the Critical Section.

Important Terms
Critical Section (CS)
Part of the program where shared resources are accessed.
Example:
database update,
printer usage,
shared file access.

Token
A special permission object.
If process has token:
Can enter CS
If process does not have token:
Cannot enter CS

Ring Structure
Process1 → Process2 → Process3 → ... → Process1
Token continuously circulates.

Why Mutual Exclusion Is Achieved?
Because:
Only one token existsOnly\ one\ token\ existsOnly one token exists
Therefore:
only one process can possess token,
only one process enters CS.

Why Deadlock Does Not Occur?
Because:
processes do not compete simultaneously,
access depends only on token possession.

What Happens If Token Is Lost?
If token is lost:
no process can enter Critical Section,
system halts.
This is called:
token loss problem
